A. BUGS IN THE CODE
================================================================================

-------------------------------------------------------------------------------
BUG 1 (HIGH): Hill-climbing boundary handling wastes evaluations
File: search_algorithms.py, hill_climbing_search()
-------------------------------------------------------------------------------
PROBLEM: When hitting a boundary (next_pos < 0 or > max_idx), the algorithm
reversed direction and halved step without evaluating the boundary point.
Combined with the same logic on "passed peak", the double reversal caused
inefficient zigzagging.

FIX APPLIED: [FIXED]
  - Added max_iter=200 parameter to prevent runaway loops.
  - Changed boundary handling from blind reversal to clamping:
    next_pos is now clamped to [0, max_idx]. If clamped position equals
    current position (truly stuck at boundary), only then halve + reverse.
    Otherwise the boundary point is evaluated, giving the algorithm useful
    information.

-------------------------------------------------------------------------------
BUG 2 (HIGH): Momentum hill climbing could converge to wrong position
File: search_algorithms.py, momentum_hill_climbing()
-------------------------------------------------------------------------------
PROBLEM: When hitting a boundary, velocity reversed with momentum_decay but
position didn't advance. The algorithm could converge to wherever it first
hit a boundary rather than the actual peak. Also no iteration limit.

FIX APPLIED: [FIXED]
  - Added max_iter=200 parameter to guarantee termination.
  - The while loop now checks `iterations < max_iter`.

-------------------------------------------------------------------------------
BUG 3 (MEDIUM): Golden Section start_idx inconsistency across scripts
File: search_algorithms.py, golden_section_search()
-------------------------------------------------------------------------------
PROBLEM: start_idx was extracted from **kwargs, making it invisible in the
function signature. run_experiments.py didn't pass it (defaulting to
max_idx//2), while benchmark_advanced.py passed start_idx=0 — inconsistent.

FIX APPLIED: [FIXED]
  - Made start_idx an explicit parameter: golden_section_search(eval_func,
    max_idx, start_idx=None, **kwargs).
  - Default None maps to max_idx // 2 internally.
  - Backward compatible: kwargs fallback preserved.

-------------------------------------------------------------------------------
BUG 4 (MEDIUM): benchmark_advanced.py passed start_idx=0 to Golden Section
File: benchmark_advanced.py, line 107
-------------------------------------------------------------------------------
PROBLEM: All algorithms (including Golden Section) were called with
start_idx=0. Golden Section should not receive a start_idx that overrides
its internal bracketing logic.

FIX APPLIED: [FIXED]
  - Added if/else to call Golden Section without start_idx and all other
    algorithms with start_idx=0.

-------------------------------------------------------------------------------
BUG 5 (MEDIUM): Brenner gradient docstring contradicts code
File: focus_measures.py, brenner_gradient()
-------------------------------------------------------------------------------
PROBLEM: Docstring said "Focus = Sum(...)" but code uses np.mean(). Also
the docstring only mentioned the x-component, not the y-component.

FIX APPLIED: [FIXED]
  - Updated docstring to:
    Focus = Mean((I(x+2,y) - I(x,y))^2) + Mean((I(x,y+2) - I(x,y))^2)
    Uses mean instead of sum for size-invariant normalization.

-------------------------------------------------------------------------------
BUG 6 (MEDIUM): exp2 shifted curve creates artificial discontinuity
File: run_experiments.py, exp2_gs_peak_shift()
-------------------------------------------------------------------------------
PROBLEM: Padding with constant floor value created a step edge at the
junction between real data and padding. Golden Section could lock onto
this discontinuity instead of the shifted peak.

FIX APPLIED: [FIXED]
  - Added scipy.ndimage.gaussian_filter1d import.
  - After constructing the shifted curve, apply gaussian_filter1d(sigma=1.5)
    to smooth the padding junction while preserving the peak shape.

-------------------------------------------------------------------------------
BUG 7 (MEDIUM): analyze_focus.py uses 1-based indexing
File: analyze_focus.py
-------------------------------------------------------------------------------
PROBLEM: Used np.arange(1, len(variances) + 1) while all other scripts use
0-based indexing. WD calculation also used (index - 1) * step to compensate.
Output was saved to the dataset directory instead of results/.

FIX APPLIED: [FIXED]
  - Changed to 0-based: np.arange(0, len(variances))
  - Updated WD calculation: 10.0 + coarse_index * 0.01
  - Added output_dir parameter to analyze_dataset()
  - Fixed __main__ to use proper base_dir/dataset_dir/output_dir paths
  - Fixed plot title to use os.path.basename(dataset_path)

-------------------------------------------------------------------------------
BUG 8 (LOW): Newton-Raphson cycle detection only catches 2-point cycles
File: search_algorithms.py, newton_raphson_search()
-------------------------------------------------------------------------------
PROBLEM: The cycle detection tried halving the step once. If the halved step
also landed on an evaluated point, it broke out. But 3+ point cycles and
direction-dependent traps were not handled.

FIX APPLIED: [FIXED]
  - Added 3-level cycle detection: original step -> halved step ->
    opposite-direction step. Only breaks if all three land on evaluated
    points.

-------------------------------------------------------------------------------
BUG 9 (LOW): Secant search near-zero division risk
File: search_algorithms.py, secant_search()
-------------------------------------------------------------------------------
PROBLEM: Guard threshold abs(df1 - df0) < 1e-6 was too tight. Values like
1.1e-6 could slip through and produce very large intermediate values before
the step clamping caught them.

FIX APPLIED: [FIXED]
  - Widened threshold from 1e-6 to 1e-4 for a more conservative guard.

-------------------------------------------------------------------------------
BUG 10 (LOW): exp8 convergence closure fragility
File: run_experiments.py, exp8_convergence()
-------------------------------------------------------------------------------
PROBLEM: The eval_func closure inside a for-loop captures variables by
reference. Works correctly but is fragile if refactored.

STATUS: [NOT CHANGED — WORKS AS-IS]
  - The pattern is correct since best_diff_history and eval_func are both
    re-created each loop iteration. Closure capture-by-reference is fine
    here. Adding a comment would be the only improvement.

-------------------------------------------------------------------------------
BUG 11 (LOW): plot_search_paths.py hardcoded title assumptions
File: plot_search_paths.py
-------------------------------------------------------------------------------
PROBLEM: Title was hardcoded to "Trapped in Local Max" for all datasets
except pollen.spd5, regardless of actual algorithm behavior.

FIX APPLIED: [FIXED]
  - Title is now dynamically determined: compares the best evaluated point's
    index against np.argmax(curve_y). If within 2 indices -> "Found Peak",
    otherwise -> "Trapped in Local Max".

-------------------------------------------------------------------------------
BUG 12 (LOW): Bare except clause silently swallows all exceptions
File: run_experiments.py, exp9_fine_peak()
-------------------------------------------------------------------------------
PROBLEM: `except:` catches KeyboardInterrupt and SystemExit, making
debugging difficult.

FIX APPLIED: [FIXED]
  - Changed to `except Exception:`.


================================================================================
B. WRONG APPROACHES / DESIGN ISSUES
================================================================================

-------------------------------------------------------------------------------
ISSUE 1: Golden Section Search assumes unimodality
-------------------------------------------------------------------------------
PROBLEM: Real SEM focus curves have noise ripples creating local maxima,
violating Golden Section's unimodality assumption. The greedy bracketing
phase may bracket a local maximum.

STATUS: [ACKNOWLEDGED — INHERENT LIMITATION]
  - This is a fundamental limitation of Golden Section Search.
  - The bracketing phase is already the best mitigation available.
  - The report correctly discusses this as a methodological consideration.

-------------------------------------------------------------------------------
ISSUE 2: Noise experiment (exp4) used random start for all algorithms
File: run_experiments.py, exp4_noise_robustness()
-------------------------------------------------------------------------------
PROBLEM: Random start_idx was generated for each trial, but Golden Section
ignores it. This meant GS was tested for noise-only robustness while local
algorithms were tested for noise + start sensitivity — an unfair comparison.

FIX APPLIED: [FIXED]
  - Changed from np.random.randint() to fixed midpoint start (max_idx // 2)
    for all algorithms, ensuring a fair noise-only comparison.

-------------------------------------------------------------------------------
ISSUE 3: exp5 scatter plot missing measure legend
File: run_experiments.py, exp5_accuracy_cost()
-------------------------------------------------------------------------------
PROBLEM: Different markers were used for different focus measures but the
legend only showed algorithm names. Users couldn't tell which dots
corresponded to which measure.

FIX APPLIED: [FIXED]
  - Added a combined legend with both algorithm colors and measure markers
    using matplotlib.lines.Line2D custom handles.

-------------------------------------------------------------------------------
ISSUE 4: 10 um per index assumption used for all datasets
File: run_experiments.py, exp5/exp6
-------------------------------------------------------------------------------
PROBLEM: abs(idx - true_peak) * 10 assumes 10 um spacing for ALL datasets.
Different pollen.spdX datasets likely have different step sizes.

STATUS: [ACKNOWLEDGED — DOCUMENTED]
  - The assumption is documented in the code and report.
  - The report now notes "assuming 10 um/index step size" where relevant.
  - A STEP_UM dict could be added when actual step sizes are known.

-------------------------------------------------------------------------------
ISSUE 5: exp7 floor region hardcoded to indices 0-40
File: run_experiments.py, exp7_measure_quality()
-------------------------------------------------------------------------------
PROBLEM: Floor defined as curve[:40] for all datasets. Some datasets may
have the peak rise starting before index 40.

FIX APPLIED: [FIXED]
  - Replaced with dynamic floor detection: finds where the curve first
    exceeds 20% of the peak-to-minimum range.
  - Enforces a minimum of 10 samples for statistical reliability.

-------------------------------------------------------------------------------
ISSUE 6: exp10 timing measures I/O with warm disk cache
File: run_experiments.py, exp10_timing()
-------------------------------------------------------------------------------
PROBLEM: After the first iteration, the OS disk cache serves images from
RAM, making I/O measurements artificially fast.

FIX APPLIED: [FIXED — DOCUMENTED]
  - Added explicit comment documenting that timings reflect warm-cache I/O.
  - Updated report to include caveat about cold-disk vs warm-cache I/O
    and note that real autofocus bottleneck is camera acquisition.

-------------------------------------------------------------------------------
ISSUE 7: exp9 bootstrap noise level was arbitrary 2% of peak
File: run_experiments.py, exp9_fine_peak()
-------------------------------------------------------------------------------
PROBLEM: Used np.max(curve)*0.02 as noise sigma. Different measures have
vastly different scales, making the 2% noise mean different SNR for each.

FIX APPLIED: [FIXED]
  - Now uses np.std(curve[:40]) — the actual noise floor statistics —
    as the bootstrap noise level. This produces a realistic and consistent
    SNR-based comparison across measures.

REPORT 1: "100% success rate" on synthetic Gaussian
File: report.tex
-------------------------------------------------------------------------------

synthetic test.

STATUS: [NO CHANGE NEEDED]

REPORT 2: "Computation costs vastly exceed modern disk I/O"
File: report.tex
-------------------------------------------------------------------------------
PROBLEM: Timing benchmark uses warm OS disk cache, making the I/O
measurement artificially fast. Conclusion may not hold for cold-disk reads.

FIX APPLIED: [FIXED]
  - Removed "conclusively" and "heavily" qualifiers.
  - Added caveat: "I/O timings reflect warm OS disk cache performance;
    cold first-access reads from a physical disk may be significantly
    slower. In a real autofocus system, the bottleneck is typically
    camera acquisition rather than disk access."
